### 3.1 이관 방식 — 왜 안 깨졌나

**경로 표가 스위치였다.** `routes.js` 에 한 줄 더하면 그 경로만 Edge 로 가고, 지우면
Railway 로 되돌아왔다. 33건을 한 번에 던지지 않고 경로 단위로 옮기며 매번 원본과
응답을 대조할 수 있었던 게 핵심이다.

**대조 하네스 63종** (`api/scripts/verify_*_parity.py`) — 원본 Python 과 Edge TypeScript 에
같은 입력을 넣고 출력을 비교한다. 그중 **14종이 CI 게이트**다.

각 하네스에는 **음성 대조**(`--negative`)가 있다. 일부러 값을 변조해 넣고 검사기가
**잡아내는지** 본다. 안 잡으면 그 하네스는 아무것도 검증하지 못하고 있다는 뜻이다.

### 3.2 Python ↔ JS 로 갈렸던 것들 (하네스가 잡은 실제 차이)

옮길 때 매번 걸린 것들이다. 새 코드를 옮길 일이 생기면 여기부터 본다.

| 차이 | 증상 |
|---|---|
| `atob` 는 패딩 없는 base64 도 받는다 | Python 이 422 낼 입력을 Edge 가 통과시킴 |
| pydantic 은 **본문 전체를 먼저** 검증한다 | 루프 안에서 검증하면 오류 순서가 갈림 |
| `String(e)` vs `str(exc)` | JS 는 `"Error: "` 접두어가 붙는다 — **4곳**에서 DB 에 저장되고 있었다 |
| Python `max()` 는 동점이면 **앞의 것** | `>=` 로 쓰면 다른 그림을 고른다 |
| `split("```", 2)` 는 **최대 2회 분할** | JS `split` 의 limit 은 의미가 다르다 |
| `.strip()` ≠ `trim()` | Python 공백 집합이 더 넓다 |
| 문자열 슬라이싱이 **코드포인트** 기준 | 한글에서 갈린다 |
| `fromisoformat` 은 2026-02-29 를 거부 | JS `Date` 는 3/1 로 넘긴다 |

→ 공용 헬퍼로 고정: `_shared/pyerror.ts` · `_shared/search/pystr.ts` · `_shared/billing/pydate.ts`

## 5. 이 프로젝트에서 반복해서 당한 함정

새로 진입할 때 이 목록부터 읽으면 같은 걸 두 번 안 밟는다.

1. **"판정이 이상하면 자[尺]를 의심한다"** — 이번 이관에서 **9번** 걸렸다.
   측정 결과가 말이 안 되면 대상이 아니라 **측정기**를 먼저 연다.
   - 이미지 대조에서 최종 JPEG 바이트를 비교 → 10건 거짓 실패. 서로 다른 인코더는
     본래 ~3dB 차이가 난다. **인코딩 전 픽셀**을 비교하도록 고쳐서 해결.
   - PPTX 대조에서 가짜 캡셔너를 주입 → 정규화된 바이트를 보게 돼 5건 거짓 실패.
2. **"선재 결함"이라 부르려면 대조 근거를 갖는다.**
   `git archive <세션시작커밋> | tar -x -C /tmp/base` 후 **같은 명령**으로 재실행한다.
   한 번은 "CI 는 원래 깨져 있다"고 결론냈다가, 대조해 보니 **내가 깨뜨린 것**이었다.
3. **Edge secret 은 `SUPABASE_` 접두어를 거부한다** — 조용히 무시된다. 그래서
   `config.ts` 가 별칭을 먼저 읽고 원래 이름으로 fallback 한다.
4. **Edge 함수 안에서 `pathname` 은 `/<함수명>/...`** 이다. 프록시를 거칠 때와 다르다.
5. **FastAPI 는 라우팅이 인증보다 먼저다.** 인증을 앞에 걸면 404·405 가 401 로 바뀐다.
6. **zsh 글롭** — URL 의 `?`, `--include=*.py` 가 확장된다. 인용할 것.
7. **Railway 대시보드는 Variables 저장만으론 redeploy 안 된다** (좌상단 보라색 Deploy).
   GraphQL `variableUpsert` 경로는 이 함정이 없다.

- 심사 완료 시 `JETRAG_KAKAOPAY_SECRET_KEY` 를 Edge secret 으로 등록하면 결제가 켜진다.
  ```bash
  supabase secrets set JETRAG_KAKAOPAY_SECRET_KEY=<값>
  ```
- 코드·cron·DB 는 전부 준비됐다. §4.3 의 503 이 정상 응답으로 바뀌면 성공.
- **미검증 1건**: `JETRAG_BILLING_KEY_ENCRYPTION_KEY` 가 Railway 시절 값과 같은지 확인
  못 했다 — 암호문이 0건이라 비교 대상이 없다. 첫 구독이 생기기 전이므로 실질 위험은 없다.

### P2 — 결정이 필요한 것

#### 7.4 `JETRAG_SYNONYM_INJECTION_ENABLED` 를 켤 것인가 ⬜

- 전체 청크 **37,080 개 중 199 개**에 `[검색어: ...]` 동의어 마커가 있다(`synonym_source="dict"`).
  기능은 이관 완료(대조 통과)됐지만 **ENV 는 꺼져 있다.**
- 켜면 재인제스트 시 그 199개가 복원된다. 안 켜고 재인제스트하면 **사라진다.**
- 판단 필요: sparse 매칭 개선 효과 vs 마커 오염. 측정한 적 없다.

#### 7.5 `golden_v1.csv` 의 죽은 40행 ⬜

- 참조하던 문서가 DB 에 없어 평가에 안 잡힌다. 두 선택지: 문서 재업로드 / 행 삭제.
- `golden_v2.csv`(182행)는 멀쩡하므로 **CI 게이트에는 영향 없다.**

#### 7.6 `api/app/` FastAPI 소스 + `api/Dockerfile` 삭제 여부 ⬜

- `api/app/` 52,890 LOC 가 배포되지 않은 채 남아 있다. `verify_*_parity.py` 가 아직
  import 하므로 **하네스를 먼저 정리해야** 지울 수 있다.
- `api/Dockerfile` 은 **Railway 전용 빌드 파일**이다(RAILPACK · `PORT` 주입 전제).
  지금은 아무도 안 쓴다 — Railway 삭제(§7.1)와 함께 지우면 된다. 의존자 없음.
- `api/migrations/` 와 `api/scripts/` 는 **현역이므로 남긴다.** `api/` 를 통째로 지우면 안 된다.
- 되돌리기 어려운 큰 변경이다. Railway 삭제 후 안정화되면 그때 판단.
