## 2. ② halfvec 전환 (마이그 036)

- 실측 전제: pgvector 0.8.0, `vector(1024)` 컬럼 2개(`chunks.dense_vec`, `documents.doc_embedding` 14행 — 후자는 그대로), `dense_vec` 참조 함수는 2개뿐.
- 설계: `ALTER COLUMN ... TYPE halfvec(1024)`(테이블 재작성) → `hnsw (dense_vec halfvec_cosine_ops)` → 함수 2개는 비교식만 `query_dense::halfvec(1024)`. 파라미터 타입은 `vector` 그대로라 **Edge 호출 코드 변경 0**. 쓰기 쪽(supabase-js 배열)은 텍스트 입력이라 그대로.
- **`supabase db query --linked` 는 statement_timeout 120s** (실측 `pg_sleep(150)` → 57014 취소, 2:03 만에). 테이블 재작성이 얼마나 걸릴지 몰라 **pg_cron 일회성 잡**으로 돌렸다: `SET statement_timeout=0` + `DO` 블록(`LOCK TABLE` 선점 → 타입이 아직 `vector` 면 실행) + 함수 재정의 + 자기 unschedule. 겹침 방지는 LOCK 뒤 카탈로그 재확인.
- 실행: 01:46:00 시작 → 01:46:37 성공. **37초.**
- 결과:

| 항목 | 전 | 후 |
|---|---:|---:|
| `idx_chunks_dense` | 265MB | **25MB** |
| `chunks` 총 | 506MB | **75MB** (힙 20MB) |
| 정확 top-50(`enable_indexscan=off`) 일치, 질의 3개 | — | 50/50 · 50/50 · 50/50 |
| HNSW 기본(ef 40) 행수 / 재현율 | 8·21·39 / 5·21·39 | 41·40·41 / 15·40·41 |
| dense DB 내부 콜드/웜 | 636~976ms / 18~22ms | 264~741ms / 19~72ms |
| 골든 120행 hybrid top-1 / top-3 / p95 | 81.7% / 89.2% / 1,438ms | **82.5% / 90.0% / 421ms** |

- 전환 전 행수가 8~39 였던 이유: SK 25k 삭제 + 필터 4,612 NULL 로 인덱스에 **죽은 엔트리**가 많아 ef_search 예산을 먹었다. 재빌드로 사라짐.
- 사후: `chunks` autovacuum **다시 켬**(재작성 직후라 죽은 행 0). VACUUM 은 불필요(재작성이 곧 압축).

### ②' ef_search=100 재실험

어제(034) 같은 설정이 dense 전용 모드를 10s 로 만들었다. 인덱스가 캐시 안에 들어간 지금 다시 잰 것:

| 모드 | ef 40 | ef 100 |
|---|---|---|
| hybrid top-1 / avg | 99/120 / 246ms | 99/120 / 217ms |
| dense top-1 / avg | 100/120 / 158ms | 100/120 / 231ms (max 1,917 1건) |
| sparse | 54/120 | 54/120 |
| PostgREST `search_dense_only(top_k 50)` 행수 | 40~41 | **50** (웜 57~78ms) |

적중률은 같고(상위 문서는 ef 에 둔감) 후보가 50개로 차서 유지. `iterative_scan` 은 안 건드림(어제 악화 원인). 034 파일에 추기. 되돌리기 한 줄도 적어 둠.

## 3. ③ 쓰기 통제 규칙 + 감시견

- `docs/ops/db-write-control.md`: 인덱스 110MB 예산(halfvec 약 40k 벡터, 넘으면 그때 상향), 대량 쓰기 = 청크 2,000행+ → 야간·한 번에 하나·감시견, 매분 cron·64/태스크 유지, autovacuum 켜 두고 대량 삭제 뒤엔 야간 수동, 120s 넘는 문장은 pg_cron 템플릿, 금지 목록.

- **첫 실행에서 오판 3건으로 큐를 두 번 내렸다** — ① macOS 에 GNU `timeout` 없음(command not found → "응답 없음") ② `ingest_jobs.stage` 는 `current_stage` ③ CLI 진행 문구(stderr)가 JSON 에 섞여 jq 실패. 수정 후 SQL 오류는 큐를 내리지 않고 exit 2 로 분리. 양성(110ms 정상)·음성 2건(SQL 오류, 임계 1ms)으로 확인하고 나서 재가동. CLAUDE.md "검출기는 양성·음성 두 케이스에서 다 돌린다"를 어긴 대가.
